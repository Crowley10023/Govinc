# Architecture Overview

## Core Purpose
Spring Boot application for security assessments along security controls and security catalogs.

## Technology Stack
- **Backend**: Spring Boot with Thymeleaf templating engine
- **Frontend**: HTML5, CSS3 (centralized in general.css)
- **JavaScript**: jQuery, organized in separate .js files per page
- **Security**: Spring Security context and SecurityConfig class

## Frontend Architecture Rules
1. **CSS**: All styles must be in centralized CSS files (general.css for common, page-specific in respective sheets)
2. **JavaScript**: All JS must be in separate .js files (never inline in HTML)
3. **HTML**: Only semantic markup and data attributes, no inline styles or scripts
4. **Accessibility**: Use semantic HTML, proper form labels, keyboard navigation

## Key Templates & Assets
- **assessment-details.html**: Main assessment editing interface with:
  - Collapsible domain sections with progress checkmarks
  - Control answer forms with AI-powered answering guide modal
  - Multi-purpose modal popups (Org Unit, Users, Org Services selection, Progress)
  - Dynamic form feedback (success/error indicators)
  - External JS: assessment-details.js
  - External CSS: general.css, answering-guide.css, style.css

- **general.css**: Shared styles including:
  - Navigation bar (60px fixed header)
  - Modal popup system (flexible layout, consistent styling)
  - Form elements (selects, textareas, checkboxes)
  - Card-based layout with shadows and borders
  - Button styles (primary, secondary, action variants)
  - Responsive grid system
  - Color variables (primary-blue, accent-orange)
  - Common utility classes (.card, .table, .modal-bg, etc.)

- **assessment-details.js**: Contains all JavaScript for:
  - CSRF token setup for AJAX requests
  - Modal state management and event handlers
  - Dynamic content loading (org units, users, org services)
  - Answering guide workflow (questions -> answers -> proposed answer)
  - Domain completeness checking with visual checkmarks
  - Answer auto-save with visual feedback
  - Word report progress polling
  - Collapsible section toggle logic

## Modal System
Unified modal pattern:
- Base: .modal-bg (fixed overlay, flexbox centered)
- Container: .modal-popup (white box, scrollable content)
- Header: .answering-guide-header (with close button)
- Content: scrollable area with semantic sections
- Footer: .modal-btn-row (flex buttons, right-aligned)

## State Management
- Global window variables for page-level state (assessmentId, securityCatalogId, etc.)
- currentAnsweringGuideState object for multi-step answering guide workflow
- DOM-based state for UI visibility (display: none/block via CSS classes)

## Data Flow
1. Page Load: Thymeleaf renders HTML with server data, collapses assessment details by default
2. User Interaction: Click handlers trigger AJAX calls or modal opens
3. AJAX Responses: Update DOM directly or reload page (for Org Services changes)
4. Feedback: Visual success/error indicators (background colors, SVG icons, status text)

## Styling Conventions
- Gradient headers using primary-blue and accent-orange
- Consistent border: 1px solid rgba(34,116,165,0.1)
- Box shadows: 0 2px 8px rgba(34,116,165,0.08) for cards, 0 10px 40px rgba(0,0,0,0.2) for modals
- Border radius: 8px for containers, 6px for form elements, 12px for modals
- Flex layout for responsive rows and button bars
- Media breakpoints: 1024px (tablet), 768px (mobile)
